**1. A — but not for the reasons in your option list, and A needs one amendment.**

Your framing is wrong in a way that decides it: **B and C are unscoped.** Both land in `styles-custom.css`, which every engine loads. "Chromium unaffected" is true of the *gate* and false of the *readers* — B's `clamp(16px,1rem,24px)` caps the form fields for Chromium and Firefox readers at ≥250% too, and C's `overflow-x` clips rows for every reader at every zoom level, today, in all three engines, because you measured the rows sticking 25px out each side in all three. So the trade is not "fix WebKit vs tolerate WebKit", it is **regress all engines at all zoom levels to remove a WebKit-only artifact at 300%**. A is the only option whose blast radius is contained to the population already experiencing the defect, and that population may be empty (see 2). C is the worst: it destroys rendered content to remove a scrollbar onto nothing. B is second worst: it freezes the text of the exact users the ticket exists to serve.

Amendment to A: write the exception where a reader would look, not in a commit body. Three places — a block comment at the end of the item-7 CSS block, a `KNOWN-WEBKIT-300.md` in `tests/overflow/`, and one line in the commit message pointing at it. The document must carry: the mechanism (input default preferred size at used font size, 85+380=465), the engine split, the four failed fixes with their measured numbers, the two working fixes and why each was rejected, the 465/477 and 1295/1307 noise, and the exact command to re-run. **2. Exception, not a conformance failure — and possibly a vacuous one.** 1.4.4's bar is 200%, 1.4.10's is 320 CSS px at default zoom. You are green in all three engines at 32px and at 16px. Root 48px is not a conformance state. What would flip me: the same mechanism at 32px in any engine, or at any root font in the 320/16 cell, or the scroll region containing anything a person could read, or a site-controlled text-size widget shipping later that offers 300%.

Add one thing to the doc that you have not established and that makes the exception much stronger: **is root 48px reachable at all in a shipping WebKit browser?** Safari has no text-only zoom; macOS "never use font sizes smaller than" tops out at 24px; iOS has no equivalent. If that holds, the exception is not a compromise, it is a state no user can enter — which is a different and much better sentence to write down. Do not claim it until you have checked the two settings pages.

**3. No. B is worse, and it is worse by your own metric.** A WebKit reader at 300% gets 49px of scrollable blank space on 49 pages. Under B, *every* reader at ≥250% in *every* engine gets form text pinned at 24px while page text is 48px. One is an empty scroll region; the other is text that stops responding to the reader's own settings, silently, on the one control they have to type into. That is the failure the whole ticket was opened to fix, reintroduced deliberately, and shipped to three engines instead of one.

**4. It has a name, sort of: this is the *default preferred size* of a form control (CSS UI 4's form-control intrinsics — `size` × average character width) leaking its unclipped descendant overflow into the ancestor's scrollable overflow area.** CSS Overflow 3 aggregates the scrollable overflow areas of unclipped descendants, so on the spec text WebKit is defensible and Blink is the one clamping. Nothing standard removes an intrinsic contribution; `contain: inline-size` only zeroes the element's contribution to its *ancestors'* intrinsic sizing, which is not your problem since the box already fits. Candidates you have not tried, in order of my confidence — and every one is a guess:

- **`appearance: none` / `-webkit-appearance: none` on the fields.** Best guess by a distance: it changes which form-control intrinsic rules apply at all.
- `inline-size: 0; min-inline-size: 100%` on the inputs — forces the used size, denies any intrinsic fallback.
- `font: -webkit-small-control` — a WebKit system-font keyword that caps the control's font implicitly. This is B in a trench coat, so it fails the same test.

But do not trust any of these as tested: see 5.
