2. TWO INSTRUMENT BUGS, IN A ROW, IN MY OWN GATE. ATTACK THIS HARDEST.

2a. The silent one, and the worst thing I nearly shipped.
gate.py applied the root-font override as `add_style_tag()` after `goto()`. I
"fixed" a double-layout problem by moving it before the navigation, and
`add_style_tag()` before `goto()` does not survive navigation at all: measured,
`getComputedStyle(documentElement).fontSize` stays 16px. Every 32px and 48px cell
became a 16px cell. Result: chromium 636/636 green, webkit 636/636 green, firefox
636/636 green, and the BEFORE run — the one that is supposed to show the defect —
also 636/636 green. Nothing in the output changed: no error, no unusual line, no
count that looked wrong. I only noticed because a before run coming back clean is
implausible enough that I went and looked at what the page was actually rendering
instead of reading the summary. My `add_init_script()` attempt at a fix was the
same failure in a different costume: at document-start `document.documentElement`
is null, the script throws, and Playwright does not surface it.
What the gate does now: (i) the root font is injected into the navigation
response itself (`route.fetch()`, one inline `html{font-size:Npx !important}`
before `</head>`), so it is in the document before first paint and there is
exactly one layout pass; (ii) a canary after the settle reads the computed root
font back off the page and exits 2 if it is not the size the cell asked for; (iii)
a styled canary (`.navbar-brand` display, `--bs-body-font-family` present) so an
unstyled page, which never overflows and would pass every cell, cannot be read as
a green matrix; (iv) a flavour canary for the before/after pair, asserting
`.navbar-brand` computed `white-space` is `nowrap` in the before run and `normal`
in the shipped run, because the pair's whole claim is "one instrument run twice"
and the run that was served the wrong payload must refuse rather than produce a
number. Measured working: the run above caught the bug three times before I fixed
it, and the fixed instrument produced the 3/3-versus-0/3 pair quoted in section 1.

Questions on this, and I want the general shape, not just this instance:
  * Have I made the failure class impossible, or have I covered the three ways I
    happened to find it? What would you assert that I have not thought of? I am
    specifically unsure about the flavour canary: it checks one property of one
    element. What else does the before/after pair need to be honest?
  * Is "exit 2 with INSTRUMENT FAILED" the right shape, or should a canary failure
    make the run print nothing at all (I currently print the failure and exit, but
    a human reading a log could still find the last summary line above it)?
  * Where else in this work am I relying on a Playwright/CSS mechanism I have not
    measured? I have been wrong twice about exactly that, both times in the
    direction of a clean green.

2b. The loud one, which was still my fault.
The first three-engine run reported webkit red at 148/636, all in 48px cells,
e.g. "scrollWidth 465 > clientWidth 390 (+75)" on many pages. A direct probe of
the same page, same viewport, same root font, showed documentElement.scrollWidth
exactly 390 — no overflow — in webkit as shipped, in webkit with my CSS cut out,
and in chromium. The 75px element was EmailOctopus's opt-in widget mid-reveal;
its honeypot is position:absolute; left:-5000px and was never the cause. The
fault: I measured 120ms after load, while the widget's entrance transform still
had it offset from the right edge, and applying the root font after load laid
every page out twice, which is what restarts that animation. Chromium did not
report it because it resolves the reveal earlier: the same one-engine-is-not-the-
whole-matrix lesson as the Firefox font-metrics row, arriving from the opposite
direction — an instrument can also invent a failure that only one engine shows.
The fix here was a settle (one jump to the bottom and back, then ~1300ms) and,
as above, getting the font into the document before first paint so there is no
second pass to restart anything. Measured one page x 3 cells at 48px: 2/3 red
with the old settle, 3/3 green now.

Questions on 2b, and I want you to try to break the fix, not agree with it:
