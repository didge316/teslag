## 3. The rules a machine actually enforces

`qa_page.py` checks 30 things per page. These are the gate's own labels from a real run —
more reliable than prose in the spec:

```
exactly one <h1>                        H2 count 5-9
h2/h3 and FAQ names title case          title <= 60 chars
description 120-155 chars               canonical self-referential, extensionless
og:url == canonical                     series kicker present
no em/en dash, curly quote or           one-line affiliate disclosure present
  ellipsis in the article body
>= 4 internal links                     no dead links (spec §12)
>= 3 links to pages that link back      no internal link to a redirecting URL
  (spec §5.2)
>= 3 page-cited quotes (1894, p. N)     Sources block present
2-3 figures in <figure class="mb-4      every <img> has alt/width/height/lazy
  pt-5">                                  + the file exists
article figure weight < 400 KB          HTML < 200 KB
no http:// links                        no comments block (D3), no css/comments.css
no book-PDF link (D4)                   affiliate link carries tid=1894_NN
affiliate rel=noopener noreferrer       JSON-LD parses; Article.citation present
  nofollow                              FAQPage valid
                                        archive.org item present
                                          (inventionsresear00martiala)
```

**Citation form is `(1894, p. N)` where N is the PRINTED page = scan file page − 18.**
That offset is the single most common way to get this wrong. Front matter has no printed
numbers, so it is cited by scan file instead.

What no machine will ever check: whether a figure actually shows what its caption says,
how a page lays out at three widths, whether an OG card is legible at 300 px. Those are
`shot_qa.py <slug>` and eyes. **A green `run_gates.py` is necessary, not sufficient.**

## 5. The quote gate: what is actually wrong (do not re-derive this)

`check_quotes.py --all-series` reports 10. I diffed every one character-by-character
against the book and read the printed pages. **2 are real. 8 are the checker's fault.**

### Real — 2 prose edits, both in `00-hub/article.md`

The quote is verbatim and on the stated page; there is simply no citation near it. Both
are in the "twelve articles" card list (lines ~93, ~96):

| fragment | printed page | fix |
|---|---|---|
| `is equivalent to a return wire` | 184 | append `(1894, p. 184)` to card 2 |
| `patent medicine` | 394 | append `(1894, p. 394)` to card 5 |

Card 6 (`is it the less a flame…`, p. 258) is currently hidden inside a mis-parsed span
and will surface as a third uncited quote once §5's tool fixes land. Cite it too.
These are not live on the site yet — the hub page has never been rendered.

### The checker's fault — 8, in five specific places

1. **`BACKTICK_RE` is `r"`([^`']{12,})'"`** — an inline-code backtick paired with a
   *later apostrophe*. In the hub it matched from `` `inventionsresear00martiala` `` to
   the apostrophe in `Tesla's` two sections later, and from `` `[sic]` `` to the
   apostrophe in `book's`. That is 2 of the 10. No draft in the series uses a backtick
   span for a book quote (checked across all 13) — the only code span is the archive.org
   item name. Make it a real code span: `` `([^`\n]{12,})` ``.
2. **The citation regex demands a closing paren right after the page list**:
   `\(1894, p{1,2}s?\. ([\d,\s]+?)\)`. So `(1894, pp. 376, 381; we take that machine
   apart in [X](y))` reads as uncited. Drop the `\)` requirement and parse the numbers
   up to the first character that is not a digit, comma or space. That is 1 of the 10
   (`03`, `about 15,000 alternations per second`) — the citation is already there.
3. **`normalise()` un-hyphenates asymmetrically.** `re.sub(r"-\s+", "", t)` only fires
   when a hyphen is followed by whitespace, so the book's line-break `two-\nphase`
   becomes `twophase` while the draft's `two-phase` stays `two-phase`. They can never
   match. Add a symmetric rule, letters only, so numeric ranges are untouched:
   `re.sub(r"(?<=[a-z])-(?=[a-z])", "", t)`. That is 1 of the 10 (`09`, p. 479 — the
   scan's text layer really does read `a twophase motor`; the draft is correct).
4. **The OCR misreads punctuation constantly and there is no tier for it.** Printed p.
   258 reads `scorch my hand {` where the book prints `?`; printed p. 151 reads
   `giving^ say` for `giving, say,`. Both drafts are right; both fail at 0.99. Add a
   **word-stream tier** between the existing space-insensitive tier and the fuzzy tier:
   compare `[a-z0-9]+` tokens in order, punctuation dropped, and *flag it* as "OCR
   punctuation normalised" the way the space-insensitive tier is flagged. Words must
   still be the book's words in the book's order — that is the rule that matters.
   That is 2 of the 10.
5. **A very weak fuzzy match is reported as a misquote.** `check_quotes.py` treats any
   match ≥0.80 as NOT VERBATIM. `Reciprocating Engine` (the official title of US patent
   514,169, in bold in `03`) scores 0.833 against `reciprocation in whi` — that is not a
   garbled quotation, it is a name from a different source the 1894 book cannot confirm.
   Only call a near-miss a defect when the words are nearly right (≥0.90); below that,
   print it as a NOTE — "phrase not from the 1894 text, verify externally" — so it stays
   visible without failing the gate. That is 1 of the 10.
   Separately, `03`'s `Tesla's oscillator` is the **label of a markdown link** to
   Wikipedia, not a quotation. Blank link labels the way headings and figure lines are
   already blanked in `quote_spans()`.

After those five, the gate should be red only on the 2–3 hub citations, and those are
five minutes of typing.

### And the performance claim in the old work order was wrong

It said caching the OCR index was "the single highest-value tool change left". Measured:
`load_pages` 0.08s, `build_index` 0.11s. The index is not the cost. The full quote pass
is ~94s of a 2m30s gate, and a profile shows why: **`difflib.find_longest_match` called
8,084,396 times from 1,152 `find_hits` calls.** Two fixes, both safe:
- `build_index` should return the sorted `vocab` (it is rebuilt inside every fuzzy call)
  and the word-stream; `find_hits` should take them from the index instead of rebuilding.
- `check_quotes.locate()` should memoise per normalised fragment — `classify()` and the
  main loop both call it for the same fragment, so every fragment is searched twice.

With the word-stream tier answering most lookups before the fuzzy tier is reached, the
full gate should drop to seconds. That matters: the harness used a 5-minute timeout and
the gate ran 3m1s. There was 1.9 minutes of headroom.

## 9. Standing rules, learned the hard way

- **A gate result describes bytes, not a file name.** `--wire` re-renders. Gate after wiring.
- **A caption edit is a pixel edit.** Prove which half of a diff moves layout; re-run only
  what that half invalidates.
- **A count in a caption needs the thing it counts named** before a reader can check it.
- **A count is its regex.** Diff the regexes before suspecting the page.
- **A workaround applied seven times is a tool defect** with a measured count.
- **The card grid has two invariants** and a wiring task checks both after.
- **Never push.** `committed:true deployed:false` is the state of every record here.
- **A `website/` commit can leave the parent's pointer to the site stale, and a stale pointer
  is the series record contradicting itself.** `--wire` and commits inside `website/` never
  move the parent's gitlink. After any site commit, make a parent commit that names the site
  commit. `M website` in the parent has two causes - a moved gitlink, or untracked content in
  the site repo (the plates ZIP, the email widget); tell them apart with
  `git diff HEAD --submodule=short -- website`, which is empty when the pointer is current.
  Measured consequence, and the fix: `books/HANDOFF-1894.md` §9.
- **Don't paper over a defect.** Record it naming file and line, or fix it.
- **The engineering log is `books/notes/BUILD-LOG.md`** (84 KB, moved out of the retired
  harness). Reference only — the rules that bind the remaining work are already in §3, §5
  and §9 of this file. Read it before doing anything unusual, not before doing anything
  in §6.
